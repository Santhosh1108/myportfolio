01 / Product perspective

I don't want to be the PM who only writes the ticket.

I want to understand the user problem, make the product decision, work with design and engineering, and learn from what gets shipped.

My edge is being able to move between product questions and the technical details needed to answer them.

I use research, user flows, PRDs, prototypes, metrics and experiments to reduce uncertainty. When the fastest way to learn is to build, I can go further into APIs, AI systems, data and implementation rather than stopping at the specification.

SpecLens

An AI-assisted product development tool that takes a rough idea through discovery, structured specification, PRD generation, critique and an early MVP prototype.

  • Designed a guided discovery workflow that asks one focused follow-up question at a time instead of forcing users to write a complete PRD upfront.
  • Created a structured product state covering the product, problem, users, goals, requirements, user stories, acceptance criteria and open questions.
  • Connected that shared state to PRD generation, critique, prototype generation and DOCX export so information is reused across the workflow.
